# Task_2 — API-тесты Stellar Burgers

Автотесты API учебного приложения Stellar Burgers.

## Проверяемые сценарии

- Создание пользователя.
- Вход пользователя.
- Изменение данных с авторизацией и без неё.
- Создание заказа.
- Получение заказов пользователя.

Тестовые пользователи создаются фикстурами и удаляются после тестов.
Идентификаторы ингредиентов запрашиваются у API.

## Установка зависимостей

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Запуск тестов

```powershell
.\venv\Scripts\python.exe -m pytest tests -v --alluredir=allure-results --clean-alluredir
```

## Allure-отчёт

Для генерации отчёта требуется установленный Allure CLI.

```powershell
allure generate allure-results -o allure-report --clean
allure open allure-report
```

## Известные расхождения с документацией

1. Создание заказа с идентификатором ингредиента `invalid_hash`:
   документация указывает HTTP 500, стенд возвращает HTTP 400
   и сообщение `One or more ids provided are incorrect`.

2. Создание заказа с ингредиентами без авторизации:
   документация содержит запрет на создание заказов гостями,
   но стенд возвращает HTTP 200 и создаёт заказ.
   Ожидаемый в тесте HTTP 401 является предположением:
   точный код отказа в документации не указан.

Обе проверки сохранены падающими до уточнения контракта.
Последний полный прогон: 19 passed, 2 failed.
После изменения структуры повторно проверены 8 тестов — все прошли.
